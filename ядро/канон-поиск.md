# Канон поиска — что страница говорит поисковику

Продолжение `ядро/канон.md`, тот же формат: правило — как проверяется — имя находки. Здесь то, что
читает не глаз человека, а робот поиска: лесенка заголовков, подписи картинок, адрес-оригинал,
разметка для поиска и слова в заголовке вкладки. Уровни 🔴 / 🟡 / ℹ️ и порядок разговора — в
`ядро/проверка.md`. Выкладывать сайт в поиск или нет — решает человек; эти правила про то, чтобы
открытая поиску страница была понятна и честна.

## Поиск и разметка

| Правило | Как проверяется | Находка |
|---|---|---|
| Главный заголовок один: ровно один `h1` | разбор заголовков страницы | `Главных заголовков не один` |
| Подзаголовки идут лесенкой, без пропуска уровня (после `h2` не сразу `h4`) | разбор заголовков в порядке документа | `Подзаголовки скачут через уровень` |
| У каждой картинки есть атрибут `alt`: описание у содержательной, пустой `alt=""` у украшения | разбор тегов `img` | `Картинка без подписи` |
| У страницы, открытой поиску, указан адрес-оригинал (`<link rel="canonical">`) | разбор головы страницы; страница закрыта от поиска — не проверяется | `Нет адреса-оригинала` |
| Копия на другом адресе, чем оригинал, закрыта от поиска | по живому адресу: хост адреса-оригинала против проверяемого | `Открыта поиску копия` |
| Разметка для поиска (`application/ld+json`) читается как JSON | разбор каждого блока | `Разметка для поиска сломана` |
| В разметке для поиска нет рейтинга и отзывов, которые сайт поставил себе сам | поиск `aggregateRating`, `ratingValue`, `review` в блоках | `Оценка самому себе в разметке` |
| Цифры из заголовка вкладки и описания есть и в видимом тексте страницы | числа заголовка и описания против текста (`3 000` и `3000` — одно число) | `В заголовке или описании цифра, которой нет на странице` |
| Дату «обновлено» на странице меняем только при настоящей правке текста | смотрят глазами по истории правок | глаза |
| Главный запрос из `поиск.md` стоит среди первых 12 слов заголовка вкладки | слова без регистра, служебные слова не в счёт, основы по первым пяти буквам; без поля — молчит | `Главного запроса нет в начале заголовка вкладки` |
| И виден на первом экране: в главном заголовке или в его тексте | те же слова против главного заголовка и текста первого экрана | `Главного запроса нет на первом экране` |
| В консоли браузера нет ошибок | `--техника` по живому адресу: ошибки страницы и консоли при открытии | `Страница ругается в консоли браузера` |
| Несуществующий адрес отвечает 404, а не «всё в порядке» | `--техника` по живому адресу: запрос по адресу, которого нет | `Несуществующий адрес не отвечает 404` |

## Оговорка про бесплатный адрес

На адресе вида `<логин>.github.io/<имя>/` поисковики не читают ни `robots.txt`, ни строку `Sitemap:` в
нём: файл они берут только из корня домена, а корень общий и не наш (подробнее — `ядро/публикация.md`
§ 5). Карту сайта там подаём руками в Search Console. Яндекс.Вебмастер подпапку как отдельный сайт не
подтверждает: подтверждение Яндекса и полноценная работа с поиском — на своём домене
(`ядро/публикация.md` § 9, § 9-bis).
