# Блоки — из чего собирается страница

## 1 · Контракт секции

Экран — не «свёрстанный кусок», а готовая форма, в которую ложится текст прототипа. Тринадцать типов на
два набора — визитка (15 файлов) и лендинг (23) в `ядро/блоки/`, всего 38. Каждый уже несёт композицию, а не
колонку слотов: карточки с иконками и главной средней, полосу крупных цифр, шаги с нитью, окна-мокапы,
стеклянные карточки на тёмном, чередование светлых и тёмных секций.

🔴 **Один экран прототипа — один файл в `сайты/<имя>/экраны/`.** Имя — `NN-<тип>.html`: `NN` — номер
экрана двумя цифрами, `<тип>` — из таблицы § 2. Берёшь шаблон из `ядро/блоки/<набор>/`, кладёшь копию в
папку работы и заполняешь **её**, а не шаблон: ядро обновляется пакетами, и правку в нём затрёт.
`собрать.py` сшивает файлы по имени, сверху вниз, и показывает страницу в двух размерах.

Контракт Б, дословно. Каждый файл блока — ровно одна секция, первая строка:

```html
<section class="блок блок--<тип> светлый|светлый второй|тёмный [фон--пятна|фон--сетка|фон--зерно]" id="экран-{{НОМЕР}}" data-тип="<тип>">
```

Первый экран дополнительно несёт класс схемы и два атрибута (контракт Б′): `блок--первый-экран первый-экран--разворот …
data-схема="разворот" data-картинка="фото"`. Внутри — `<div class="блок__внутри">…</div>`. Слоты: `{{ИМЯ}}` (буквы
А-Я, Ё, `_` и номер: `{{ПУНКТ_2}}`), `{{СВЯЗЬ:Текст кнопки}}` → главная кнопка или виджет (`собрать.начинка_связи`),
`{{ИКОНКА:имя}}` → инлайн-SVG (`собрать.подставить_иконки`), картинка всегда `<figure class="фото">
<img src="img/{{ФОТО}}" alt="{{ПОДПИСЬ_ФОТО}}"></figure>` (или `.мокап`, `.аватар`).

Классы — только из стилей ядра (`ядро/блоки/стили-база.css` и `ядро/блоки/стили-первый-экран.css`): `карточки` · `карточка` (`--главная`, `--стекло`), `цифры` · `цифра`,
`шаги` · `шаг__номер`, `details.вопрос`, `контакт`, `figure.мокап` (видео только внутри него — голый `iframe`
схлопывается), `пара`, `цитата` · `цитата__кто`, `бейдж`, `разделитель`, `таймер`. Двенадцать деталей первого
экрана (`чип`, `шапка`, `хвост`, `галка`, `пятно`, `остров`, `рамка-телефона`, `плей`, `плашка`, `нода`,
`спутник`, `ячейка`/`бенто__ячейка`) и переписанный `кикер` — что это, откуда сняты, на каких токенах —
`ядро/дизайн/детали.md`. Что в файле можно стереть — в комментарии под первой строкой.

**Одиннадцать схем первого экрана** — выбор по строке «Схема первого экрана» в `## Решения`
`сайты/<имя>/дизайн.md` (её пишет человек на витрине обложек, ты только переносишь, `ядро/дизайн-система.md`
§ 5). Старые имена v2 — `фото` и `постер` — читаются как синонимы `разворот` и `афиша-с-экраном`.

| Схема | Когда берём | Тип картинки | В каком наборе | Светлота свободна? |
|---|---|---|---|---|
| разворот | услуга от человека: текст слева, фото справа — самая спокойная и самая надёжная схема | фото | визитка · лендинг | да |
| орбита | вокруг человека четыре доказательства: цифры, документ, срок, награда | вырез | визитка · лендинг | нет — тёмная по рецепту |
| сцена | атмосфера важнее лица: помещение, процесс, город — кадр во весь экран | фото | визитка · лендинг | нет — тёмная по рецепту |
| живая-сцена | то же, но кадр живой и говорит: 15–20 секунд речи, без субтитров, звук — по кнопке | видео-с-голосом | визитка · лендинг | нет — тёмная по рецепту |
| афиша-с-экраном | продукт — это экран: сервис, курс, бот; есть вторая ссылка «Подробнее» | мокап | только лендинг | нет — тёмная по рецепту |
| товар-крупно | товар или приложение крупно, три преимущества бейджами | товар | визитка · лендинг | да |
| бенто | много разного сразу: текст, фото, три цифры, три пункта — плиткой | фото | визитка · лендинг | да |
| центр | человек в центре буквально: фигура посередине, карточки по бокам | вырез | визитка · лендинг | нет — тёмная по рецепту |
| живая-обложка | событие, студия, мастерская — 6–10 секунд живого кадра во весь экран | видео | только лендинг | нет — тёмная по рецепту |
| живой-портрет | человек «оживает» в кадре: дышит, поворачивается — 8 секунд | живой-портрет | визитка · лендинг | нет — тёмная по рецепту |
| мозаика-роликов | продукт — это ролики: рилсы, уроки, кейсы — пять кадров лентой | мозаика | только лендинг | нет — тёмная по рецепту |

**Зеркальный разворот.** Тот же рецепт `01-первый-экран-разворот.html`, поле «Сторона: слева» —
не косметика, а самостоятельная карточка в каталоге схем (задача 6, 10.09.2026): берут её, когда
лицо на фото смотрит к тексту, человек известнее оффера, портрет работает печатью доверия, а сам
оффер можно сказать коротко (одна строка на компьютере). На телефоне у зеркала и обычного разворота
разницы нет — фото всё равно ложится сверху во всю ширину. Каталог показывает обе карточки —
«разворот» и «разворот-слева» — рядом, а не по одной за раз по флагу `--сторона`.

Выбирают схему не по описанию, а глазами: каталог схем `ядро/обложки/каталог/обложки.html`, потом
примерка `обложки.py сайты/<имя>` на своих текстах и картинке (`ядро/дизайн-система.md` § 5). Всего
блоков в системе — 38.

Тип — это форма, а не смысл: «Бонусы» ложатся в три карточки `02-боль`, «Что получите» — в шаги
`05-программа`; `data-тип` при этом не переименовывай. Добирать из соседнего набора можно: на визитке
пригодился кейс из лендинга — бери, наборы устроены одинаково.

## 3 · Слоты: чем заполнять

`{{ИМЯ}}` — заглавными, кириллицей, номер через `_`. Повторяемые элементы даны нужным числом (три
карточки, четыре шага, пять вопросов); лишние стираются **целиком, вместе с тегом**, а не оставляются
пустыми. Заглушка, оставшаяся в собранной странице, — 🔴 у `собрать.py` и у `проверить.py`. Один слот может
стоять дважды — `{{КОНТАКТ_АДРЕС_1}}` в `href` и в тексте ссылки: заполняй каждое место тем, что там нужно.

| первый-экран, все схемы | `{{КИКЕР}}` `{{ЗАГОЛОВОК}}` `{{АКЦЕНТ}}` (последнее слово заголовка, подсвечено) `{{ПОДЗАГОЛОВОК}}` `{{ПУНКТ_1}}` `{{ПУНКТ_2}}` `{{ПУНКТ_3}}` `{{ЦИФРА_1}}` `{{ЦИФРА_2}}` `{{ЦИФРА_3}}` `{{ПОДПИСЬ_ЦИФРЫ_1}}` `{{ПОДПИСЬ_ЦИФРЫ_2}}` `{{ПОДПИСЬ_ЦИФРЫ_3}}` `{{ДОВЕРИЕ}}` `{{КОГДА}}` (когда стартует поток — необязательное, «нет» или пусто → строка убирается целиком, `прототип-поля-первого-экрана.md` § 3) + связь |

## 4 · Спецслоты: связь и иконка

`{{СВЯЗЬ:Текст на кнопке}}` — одно место на весь блок, где человек делает шаг. Текст после двоеточия —
слово в слово из строки «Кнопка» прототипа. Начинку подставляет `собрать.py` по профилю: телеграм, max,
вк, whatsapp — кнопка со ссылкой, `форма` — ссылка на чужую форму, `виджет` — код из
`профили/<имя>/виджет.html`. **Блок не знает, кнопка там или виджет** (ТЗ § 7.10-bis): сменился способ —
страница пересобирается, блоки не трогаем. Связь не задана — кнопка на экран контактов и 🟡. Три пути —
`ядро/связь.md`. 🔴 Класс `кнопка--главная` в блоке не пишут: его ставит только сборщик; вторая ссылка
первого экрана — `кнопка кнопка--контур`, и других кнопок на экране нет.

`{{ИКОНКА:имя}}` — инлайн-SVG из `ядро/блоки/иконки/` (цвет — от текста, размер — от роли: плитка 2em,
пункт списка 1.5em). Имён 60 — набор, спецификация, роли, подбор по смыслу пункта и что делать при
нехватке — всё в `ядро/иконки.md`, здесь не дублируем. Нет имени — 🔴 «Нет такой иконки» со списком всех
60. Эмодзи и стоковые наборы вместо иконки — нет (`ядро/картинки.md`).

## 5 · Светлота, атмосфера, чередование раскладок

**Светлота.** У секции один из трёх наборов: `светлый` · `светлый второй` (фон `--цвет-фон-2`) ·
`тёмный`. Шаблон даёт лишь умолчание: **светлота чередуется по соседу сверху** — ты смотришь на
соседей, а не на файл. Иначе страница читается одним полотном, и человек не видит, где кончилась мысль.
Финал и контакты по рецепту тёмные — это и есть чередование, а не «скачок». ⛔ Скачок — это два тёмных
или два светлых подряд: граница между ними пропадает, и экран сливается с соседом. У первого экрана
своё правило: светлота меняется только у схем разворот и товар-крупно; сцена, живая сцена, живая
обложка, орбита, центр, афиша-с-экраном и мозаика-роликов — тёмные по рецепту, бенто — светлая
страница с одной тёмной ячейкой по рецепту (задача 8: раньше стояла в свободной светлоте и
перекрашивалась целиком в тёмную, макет её всегда держит светлой); полем «Доминанта» это не
переставить (`ядро/дизайн-система.md` § 6).

**Атмосфера.** `фон--пятна` (мягкие пятна света), `фон--сетка` (сетка, тающая к краям), `фон--зерно`
(бумажное зерно) — только на первом экране и в финале, по полю «Атмосфера» из `## Решения`. На
остальных экранах — чистый фон.

**Раскладки.** Соседние экраны не должны быть одной структуры: после трёх карточек — пара колонок, шаги или
цитата, а не ещё три карточки. Проверяющий отметит «Все секции одной структуры» — переставь экраны или возьми
другую форму из соседнего набора. И — 🔴 **телефон первым, одобрение = оба размера**: компьютер только раскладывает колонки.

## 6 · Таймер

Живёт только в финале: `<div class="таймер" data-дедлайн="…">` с тремя `.таймер__ячейка` и строкой
«До {{ДЕДЛАЙН_СЛОВАМИ}} (МСК)». Дата — ISO с московским смещением, `2026-10-01T23:59:00+03:00`, и то же
число словами рядом. Тикает `ядро/блоки/таймер.js` (его подключает `собрать.py`): дата прошла — таймер
прячется сам, строка «До …» остаётся, поэтому просроченная дата — 🟡 «Таймер без живой даты» и от
сборщика, и от проверяющего. **Нет даты — удали карточку с `.таймер` целиком и строку с
`{{ДЕДЛАЙН_СЛОВАМИ}}`:** нули на экране хуже пустоты.

## 7 · Чего в блоках нет и почему

| Чего нет | Почему |
|---|---|
| три одинаковые карточки подряд | форма без ритма: карточки различаются иконкой, цифрой или главной средней |
| `style=""` и цвет числом (hex) | палитра — в `сайты/<имя>/дизайн.md`; в блоке только классы и `var(--…)` |
| `<style>` внутри блока | стиль в двух местах разъезжается на третьей правке |
| вторая `кнопка--главная` | одна главная на экран; вторая ссылка — контурная |
| наблюдатель пересечений, появление при прокрутке | решение 09.09.2026: движение — пульс кнопки, подъём карточки, плавные переходы |
| картинка вне обёртки `фото` / `мокап` / `аватар` | без обёртки нет скругления, тени и маски — и снова плоско |
| `<track>` у видео первого экрана | субтитров не бывает нигде — живая сцена и живая обложка говорят сами (GC 25) |
| `loading="lazy"` у картинки первого экрана | она первая, что видит человек — грузим сразу, а не по мере прокрутки |
| `object-fit` в разметке | пропорции держат стили: `object-fit` только в стилях ядра, в html — только класс |
| картинки в коде | картинка лежит в `сайты/<имя>/img/`, в блоке — только ссылка на неё |
| `<form>` | можно, но сначала `ядро/связь.md`: форма делает человека оператором персональных данных |

**Свой блок.** Нужного экрана нет — не выдумывай разметку с нуля: скопируй ближайший файл в
`сайты/<имя>/экраны/NN-<тип>.html`, переименуй тип в двух местах (класс `блок--<тип>` и `data-тип`), оставь только
классы из стилей ядра и переменные из `дизайн.md`, проверь на телефоне первым. 🔴 В ядро свои блоки не кладём: обновление ядра их затрёт.
